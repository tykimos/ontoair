# OntoAir — Web Service Deployment

Public URL: **https://poc.aifactory.space/ontoair**

OntoAir ships as a macOS QuickLook app, but the same static client (Three.js +
`ontoair.js`) also runs as a plain web page. This document describes the web
harness that serves it under `/ontoair`.

## Architecture

```
  browser ──https──▶ upstream LB (nginx, DNS poc.aifactory.space
                       → 52.78.5.37 / 15.165.66.29, TLS terminates here)
          ──http──▶ POC box (13.209.206.4) nginx, server_name poc.aifactory.space
                       location /ontoair/  →  alias  <repo>/web/   (static)
```

- **TLS is terminated at the upstream load balancer.** DNS for
  `poc.aifactory.space` does **not** point at the POC box; it points at the LB,
  which forwards every path for this Host to the POC box over plain HTTP.
  Therefore **no certbot / Let's Encrypt is needed (or possible) on the POC
  box** — HTTPS already works for `/ontoair` the moment the location is added.
- The app is **fully static**: no application process, served straight from
  disk by nginx. The QuickLook build (`scripts/build.sh`) is unaffected.

## The webroot: `web/`

`web/` is generated by `scripts/build-web.sh` and is **git-ignored** (a build
artifact). It contains:

| entry | what |
|-------|------|
| `index.html` | generated from `resources/dev.html`: `../test/` → `test/`, production title + favicon, dev-only chrome (DEV badge + raw-source viewer) hidden, **responsive/mobile layout** injected (viewport meta + `@media (max-width:768px)`: side panels become overlay drawers, collapsed by default; controls wrap; loading modal fits; `touch-action:none` for canvas gestures) |
| `*.js`, `mediapipe/` | symlinks to `../resources/*` so `dev.html`'s same-directory script/worker references resolve unchanged |
| `test/` | symlink to `../test` — the sample ontologies; nginx `autoindex` powers the in-app sample browser |

Why symlinks + a generated index instead of serving the repo root: it exposes
**only** the client assets and samples (never `.git`, `build/`, `.claude`, …),
and keeps a clean `/ontoair/` URL.

## Rebuild / redeploy

After editing `resources/dev.html`, `resources/ontoair.js`, or adding samples
under `test/`:

```bash
./scripts/build-web.sh      # regenerates web/ (index.html + symlinks)
```

No nginx reload is needed for content changes (static files are read live;
symlinks point at the working tree). Reload nginx only if you change the
location block:

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## nginx config

The live config is the `poc.aifactory.space` server block in
`/etc/nginx/sites-available/Poc` (symlinked from `sites-enabled/`). The
`/ontoair` locations are mirrored in this repo at
[`deploy/nginx-poc-ontoair.conf`](deploy/nginx-poc-ontoair.conf) for reference
and re-application.

Key detail: `absolute_redirect off` is set so the `/ontoair → /ontoair/` and
trailing-slash redirects keep the original **https** scheme (without it nginx
emits `http://` Location headers, because `$scheme` is `http` behind the LB).

## Chat backend (ontology Q&A + edit)

The page has a bottom-left chat (`resources/chat.js`, injected into the prod
index): ask about the loaded ontology, or tell it to edit. It POSTs the current
ontology text + message to `/ontoair/api/chat`.

- **Backend**: `server/ontoair-chat-server.js` — a dependency-free Node proxy to
  **Azure OpenAI**, using the **same resource/model as the nfs (autopsy)
  service** (`gpt-5.2-chat`, api-version `2024-10-21`). Config is read from
  `/home/ubuntu/poc/ontoair/.env` (git-ignored; copied from
  `../nfs/autopsy/.env.local`). The browser never sees the API key.
- **Service**: runs via systemd on `127.0.0.1:8790`
  (`deploy/ontoair-chat.service` → `/etc/systemd/system/ontoair-chat.service`,
  `enable --now`). `sudo systemctl status ontoair-chat`.
- **nginx**: `/ontoair/api/` proxies to `:8790`
  (`deploy/nginx-poc-ontoair-api.conf`, inside the same server block).
- **Behavior**: the model calls one of two tools — `search_answer` (Q&A) or
  `edit_ontology` (returns the full updated Turtle). On edit, the client
  re-renders the new TTL in place (via the existing `sessionStorage.devFile`
  reload path) and offers a download — **server-side sample files are never
  modified**. Edits live only in the browser session.

Update after editing the backend: `sudo systemctl restart ontoair-chat`.
After editing `chat.js`: `./scripts/build-web.sh` (symlinked, served live).

## Notes / limitations

- Camera-based hand-gesture control (MediaPipe) needs a secure context —
  it works because the public origin is HTTPS. (It would not work over plain
  HTTP except on `localhost`.)
- Sample `.ttl/.trig/.owl` files are served as `application/octet-stream`; the
  app reads them as text via `fetch().text()`, so MIME type does not matter.
